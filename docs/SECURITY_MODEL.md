# Security model and deployment limits

Treat user messages, model proposals, provider replies and computed outputs as untrusted. Trusted application code owns registry entries, flags, resource bounds and helper selection. No prompt can change endpoint URLs, keys, files or execution limits. Provider text/tool suggestions never become executable instructions.

The sandbox guest boundary is Monty's Rust Python-subset interpreter. OMO supplies no mounts, OS handlers, host objects, reflection, network functions or guest-callable callbacks. Missing capabilities fail closed. The application may use HTTP for a configured external model while the guest cannot: Monty has no network capability or network callback, independently of the application's network namespace. A configuration flag alone is not that boundary.

The native Monty pool uses subprocess workers and clears the environment. An OMO launcher additionally closes non-standard inherited descriptors, redirects diagnostic stderr to the null device, and applies 512 MiB address-space, two CPU-seconds, zero core/file size and 64-FD limits. The language allocator limit is 8,000,000 bytes; it is not RSS. Guest CPU work is capped at 0.1 s, recursion 32, suspension round trips 2, input/output 8 KiB and code 4 KiB. Outer wall timeout is 1.5 s including checkout, parsing, output handling and IPC; per-turn worker timeout is 1 s. There is no independent instruction/fuel counter in this Monty API, so work is bounded by CPU/wall limits rather than a fabricated fuel setting.

Two concurrent workers maximum; one checkout per worker. New guest state is used for every request and workers are discarded after errors, limits, cancellation and success. No snapshots or cross-user caches exist. The print sink discards content with an output cap. Native crash faults are contained and workers reaped. Tests use a real canary file, parent environment secret and deliberately inheritable descriptor, not mocks. Tests account for nested PID namespaces when observing their own children.

Trusted computing base: host OS/container runtime, Python, application code and dependencies, Monty native interpreter/pool/protocol, llama.cpp model parser/inference engine, and the pinned artifact. SHA validation ensures the selected bytes, not their inherent safety. Native vulnerabilities and OS-level attacks remain possible. This is not VM-grade hostile multi-tenant isolation. Keep the service private until broader security and platform gates are complete.

Container defaults: non-root UID 10001, read-only root, small noexec/nosuid tmpfs, no capabilities, no-new-privileges, bounded memory/CPU/PIDs and host-loopback publishing. There is no Docker socket, host network, privilege escalation, host credential mount or unconfined seccomp requirement. The public app process may need network only for explicitly configured providers; offline validation runs the entire image with `--network none`.

One persistent inference worker is separately supervised; no per-web-worker duplicate model. Graceful service shutdown kills/waits for native model workers and closes Monty/provider resources. Request cancellation can force a model reload and temporarily lower readiness. Runtime startup fails on artifact mismatch. Runtime cannot access GitHub-write, Docker-push, Hub-publish or Jobs credentials; do not mount those credentials. Provider keys belong only to the application environment.

Raw prompts, completions, tool values and training-data capture are disabled. Operational logs contain generated request ID, finite action/status and duration. Validation errors exclude input values; native model diagnostics are suppressed. Operational metrics are not a learning dataset. Original synthetic evaluation responses are explicitly recorded offline and contain no user traffic.

Remaining work: independent adversarial review, broader malformed native-input fuzzing, container vulnerability scanning/signing, robust authentication for multiple tenants, and operating-system isolation stronger than a shared container. See TODO.md for acceptance criteria.
